Q044 发生一次 API 超时后按既定策略重试，已计入次数和延迟。没有删除失败题或单独重跑到成功。13 次运行错误的异常链根类型为 11 次 `ProviderError`、2 次 `ValidationError`；日志只保留脱敏类型，不能据此逐一断定具体格式原因。

生成模型为 `Qwen/Qwen3.5-9B`，embedding 为 `Qwen/Qwen3-Embedding-0.6B`、1024 维，服务地址为 `https://api.siliconflow.cn/v1`。候选 32、上下文最多 12 个片段，正文预算 24,000 字符，元数据和提示词另计，生成上限 2,048 token。语料向量已预建，开发问题向量统一预热，本轮无查询 embedding API 调用。失败请求缺失的用量不能补造，费用以实际账单为准，未核实单价不填虚构金额。

运行环境为 Windows 11，系统报告物理内存总量约 29.79 GiB。整机指标包括其他后台进程；Windows 返回的 swap 换页计数为零，不能据此断言没有换页。采样峰值不是操作系统保证的绝对峰值。baseline 已获准超出 2 GiB，本轮没有执行 Linux 整机资源验收。

## 辅助指标审计

- 来源命中 184/208（88.46%），接受真实附件标题或母文件标题。这是来源层面的粗指标，不代表找到支持答案的具体条款。
- 工作表/单元格/页码定位命中按固定适用分母为 **65/70（92.86%）**。标注粒度因题而异，不能解释为统一的细粒度证据 Recall。
- 收尾发现原始异常分支漏计仅带工作表标注的 Q091、Q094，使原始定位分母为 68；两题应作为定位失败计入。原始 `report.json` 和逐题结果保留，修正口径另存 `report-audited.json`。正确率、拒答、错误数及其他指标未改动；运行时代码修复留待后续明确范围。
- 没有细粒度引用原文 gold，且 B0 未启用校验器，本报告不宣称完整引用忠实性成绩。
- 旧语料的 `dev-b0-01` 与中止的 `dev-b1-01` 只作诊断，不能与本轮混合计算组件收益。新快照的 B1–B4 未启动。

## 证据与限制

进程峰值不包括独立 Qdrant 进程，不能用它证明整机 2 GiB 通过。整机指标与运行环境在各报告中单独保存。
检索延迟包含查询向量缓存读取；比较前统一预热开发问题。生成 API 的服务端缓存与远程负载不完全可控。
API 费用按实际 token 与已核实单价计算；未核实的金额不填零。
开发集用于组件选择，不能据此宣称保留测试集提升或统计显著。
